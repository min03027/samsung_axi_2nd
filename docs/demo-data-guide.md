# 역할별 데모 데이터 가이드

## 목적

P0-02 데모 데이터는 운영 데이터와 분리된 환경에서 관리자·강사·수강생 화면이 같은 과정 데이터를 바라보는지 검증하기 위한 최소 연결형 세트다. 실제 개인정보, 운영 DB 데이터, 외부 저작물은 사용하지 않는다.

## 안전 원칙

- `demo` 프로필과 `LMS_DEMO_SEED_DATA=true`가 **동시에** 있어야 DB 시드가 실행된다.
- 공통 및 운영 기본값은 OFF다. `prod` 프로필에서는 플래그를 켜도 초기화 빈이 로드되지 않는다.
- Docker Compose 운영 구성은 DB 데모 시드 플래그와 비밀번호를 컨테이너에 전달하지 않는다.
- 화면용 메모리 샘플(`LMS_DEMO_SAMPLE_DATA`)도 운영 기본값은 `false`다.
- 계정·과정 고유 키가 일부라도 기존 데이터와 충돌하면 덮어쓰지 않고 세트 전체 생성을 건너뛴다.
- 같은 완성 세트가 존재하면 두 번째 실행부터 아무 데이터도 추가하지 않는다.
- 테스트가 끝난 데모 DB는 폐기한다. 운영 DB에 이 절차를 적용하지 않는다.

## 실행 방법

PowerShell에서 임시 비밀번호를 현재 프로세스에만 설정한 뒤 실행한다.

```powershell
$env:SPRING_PROFILES_ACTIVE = "demo"
$env:LMS_DEMO_SEED_DATA = "true"
$env:LMS_DEMO_PASSWORD = "<임시 데모 비밀번호>"
.\gradlew.bat bootRun
```

검증 후 해당 터미널을 닫거나 환경변수를 제거한다. `LMS_DEMO_PASSWORD`가 비어 있으면 시드는 실패하고 데이터는 생성되지 않는다.

## 생성되는 데이터

| 구분 | 식별값 | 연결 |
|---|---|---|
| 운영관리자 | `demo_admin` | 과정 공지 작성자 |
| 담당강사 | `demo_instructor` | 주강사로 동일 과정 배정 |
| 수강생 | `demo_trainee` | 동일 과정 승인 수강 |
| 과정 | `DEMO-AI-DATA-001` | `[DEMO] AI 기반 데이터 분석 과정` |
| 학습 데이터 | 과목 1, 차시 3, 문서 콘텐츠 2 | 어제·오늘·내일 일정과 25% 과정 진도 |
| 상태 데이터 | 출석 1, 콘텐츠 진도 1, 공지 1 | 수강생·강사·관리자 홈 실제 조회용 |

모든 계정은 동일한 `LMS_DEMO_PASSWORD` 값을 사용한다. 비밀번호는 저장소나 문서에 기록하지 않는다.

## 역할별 확인

1. `http://localhost:8080/login`에서 각 데모 계정으로 로그인한다.
2. 관리자는 `/admin`, 강사는 `/instructor`, 수강생은 `/trainee`로 이동하는지 확인한다.
3. 관리자 과정 목록, 강사 담당 과정, 수강생 내 과정에서 과정 코드 `DEMO-AI-DATA-001`이 같은 과정 ID로 조회되는지 확인한다.
4. 수강생 홈에서 오늘 14:00 차시, 콘텐츠 진도, 출석, 과정 공지가 실제 DB 데이터로 표시되는지 확인한다.

## 비활성 검증

```powershell
$env:SPRING_PROFILES_ACTIVE = "demo"
$env:LMS_DEMO_SEED_DATA = "false"
Remove-Item Env:LMS_DEMO_PASSWORD -ErrorAction SilentlyContinue
.\gradlew.bat bootRun
```

이 상태에서는 `demo_*` 계정과 `DEMO-AI-DATA-001` 과정이 생성되지 않아야 한다.

## 멱등성

완성된 데모 세트가 이미 있으면 초기화기는 관계와 콘텐츠를 확인한 뒤 추가 저장 없이 종료한다. 동일 로그인 ID 또는 과정 코드가 일부만 존재하거나 역할·과정명이 다르면 기존 값을 수정하지 않고 세트 전체 생성을 건너뛴다.

## Production 적용 금지 및 승인 절차

현재 운영 DB 입력은 승인되지 않았다. `prod` 프로필에서는 초기화기가 로드되지 않으며 Compose도 `LMS_DEMO_SEED_DATA`와 `LMS_DEMO_PASSWORD`를 전달하지 않는다. 향후 운영 시연 데이터가 필요하면 별도 승인, DB 백업, 고유 키 충돌 사전 조회, 적용 창구와 책임자 확정 후 별도 배포 변경으로 진행한다.

## Cleanup 정책

이번 P0에는 자동 삭제 기능을 만들지 않았다. 데모 프로필은 메모리 H2의 `create-drop` DB를 사용하므로 프로세스 종료 시 데이터가 폐기된다. 운영·공유 DB에서 전체 `DELETE`, `TRUNCATE`, 스키마 재생성 명령을 사용하지 않는다.

## 테스트

자동 테스트는 플래그 OFF/ON, 계정·과정·관계 생성, 동일 과정 ID 조회, 재실행 멱등성, 기존 키 비덮어쓰기, 운영 프로필 차단, 기존 로컬 초기화 회귀, 세 역할 로그인 및 홈 렌더링을 검증한다.
