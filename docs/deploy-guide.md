> 서버 내부 구성·트러블슈팅은 `docs/deploy-remote-2026-07-29.md` (서버 관리자용 런북) 참고.

## 서비스

- 운영 주소: **https://lms.samsungax.com** — 수강생이 실제로 쓰는 서버다
- 원격 저장소: https://github.com/min03027/samsung_axi_2nd — 코드·화면·배포를 모두 여기서 처리한다 (리모트 이름은 PC 마다 다를 수 있으니 `git remote -v` 로 확인)
- 서버는 사무실 PC(WSL2 + Docker)이며, GitHub Actions self-hosted 러너가 배포를 대행한다

## 배포 방법 — 태그 푸시가 전부

```bash
# 1) 로컬 테스트 통과 확인
./gradlew test

# 2) main 푸시 (이것만으로는 배포되지 않는다)
git push origin main

# 3) 다음 번호로 태그를 찍어 푸시 → 이 순간 배포가 시작된다
git tag | sort -V | tail -1          # 현재 마지막 태그 확인 (예: v0.1.2-draft)
git tag v0.1.3-draft
git push origin v0.1.3-draft
```

태그가 푸시되면 자동으로: **GitHub 러너가 전체 테스트 → 통과 시 서버가 해당 태그를 checkout + `docker compose up -d --build` → `/login` 200 헬스체크**. 진행 상황과 로그는 저장소 **Actions 탭**에서 본다. 테스트가 실패하면 배포되지 않는다(안전장치).

- **main 푸시 = 코드 공유** (서버 영향 없음, 자유롭게)
- **태그 푸시 = 배포 결정** (빌드 중 3~5분 서비스 순단 — 배포 타이밍은 서로 한마디 하고 진행)

## 규칙

1. **태그 푸시 전 로컬 테스트 필수.** CI 가 한 번 더 돌긴 하지만, 실패하면 어차피 배포가 안 되고 시간만 버린다.
2. **`.env`·API 키·비밀번호는 절대 커밋 금지.** **공개 저장소이므로 커밋 즉시 외부에 노출되고**, git 히스토리에 영원히 남는다. 비밀값은 서버의 `.env` 에만 있고(git 밖), 새 항목이 필요하면 `.env.example` 에 빈 항목만 추가한다.
3. **새 환경변수를 쓰는 기능은 값이 없어도 앱이 뜨게 만들 것** (기능만 꺼지도록 기본값 처리 — AI 기능 방식 참고). 서버 `.env` 반영은 서버 관리자(박찬웅)에게 요청.
4. **푸시 대상은 위 저장소 하나뿐이다.** 예전 저장소 리모트가 로컬에 남아 있으면 제거할 것 — 잘못 밀면 팀원이 옛 코드를 보게 된다.
5. 서버에 직접 들어가 파일을 고치지 말 것 — 다음 배포의 `checkout --force` 로 전부 사라진다. 수정은 반드시 git 을 거친다.
6. (서버 작업 시) **`docker compose down -v` 절대 금지** — DB·업로드 볼륨이 삭제된다.

## 문제가 생기면

| 증상 | 대응 |
|---|---|
| Actions 에서 test 빨간 X | 로그에서 실패 테스트 확인 → 코드 수정 → 새 태그로 재배포 |
| deploy 빨간 X | 로그 마지막에 서버 app 로그가 찍혀 있음 → 원인 파악, 안 되면 서버 관리자에게 |
| 러너가 Offline (deploy 가 안 잡힘) | 서버 쪽 문제 — 서버 관리자(박찬웅)에게 연락 |
| 배포 후 사이트 이상 | **직전 태그로 재배포하면 롤백**: `git push origin` 으로 이전 태그를 Actions 수동 실행(Run workflow)하거나, 새 revert 커밋 + 새 태그 |
| 급한데 CI 가 전부 안 됨 | 서버 관리자가 RDP 수동 배포 가능 (런북 §6-2) |
