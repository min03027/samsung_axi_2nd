# 후기 통합 CMS v1

## 1. 작업 기준

- 기준 브랜치: `integration-trainee-management-20260823`
- 기준 체크리스트: `참고문서/체크리스트/구현체크리스트_2차_20260822_정리본.xlsx`
- 확인 항목: `공통-003`, `공통-004`, `취업-015`, `취업-017`, `취업-018`
- 이 문서는 공개 홈페이지용 수강생·수료생 후기 CMS의 데이터 경계와 운영 규칙을 기록한다.
- 기존 강의 만족도 `Survey/SurveyResponse`와 과제 코멘트 `Feedback`은 변경하거나 공개 후기로 재사용하지 않는다.

## 2. 기존 구조 확인

작업 전 공개 후기는 캠퍼스와 메인 홈페이지 HTML에 이름·직무·문구가 고정되어 있었다. 후기 엔티티, 관리자 CRUD, 공개 API, 과정·취업기업 연결, 공개 동의 구분, 후기 목록/상세 필터는 없었다. 따라서 고정 문구가 실제 운영 데이터처럼 노출될 수 있었고 관리자에서 변경할 수도 없었다.

## 3. 데이터 모델

`StudentReview`는 다음 정보를 관리한다.

- 기본: 제목, 본문, 표시명, 표시 방식(실명/마스킹/익명), 콘텐츠 유형
- 교육: 과정, 기수 스냅샷, 수료 연도
- 취업: `PartnerOrganization` 기반 취업 기업, 직무, 취업 여부
- 인터뷰: 훈련 전 상황, 과정 경험, 프로젝트 경험, 취업 과정, 현재 직무
- 미디어: 이미지 URL, 영상 URL
- 노출: 공개 여부, 노출 사이트, 노출 위치, 대표 여부, 순서, 사용 상태
- 동의: 홈페이지 공개, 이미지 공개, 취업정보 공개, 영상 공개 동의
- 내부: 운영 메모, 동의 확인 일시

이미지와 영상은 v1에서 URL만 저장한다. 별도 파일 업로드·스토리지·변환 기능은 만들지 않았다.

## 4. 관리자 CMS

- 목록: `/admin/reviews`
- 등록: `/admin/reviews/new`
- 상세: `/admin/reviews/{id}`
- 수정: `/admin/reviews/{id}/edit`
- 권한: 기존 보안 정책을 그대로 사용해 `ADMIN`만 접근하며 `INSTRUCTOR`는 접근할 수 없다.
- 과정은 기존 `Course`, 취업 기업은 기업·기관 CMS의 `PartnerOrganization`을 선택한다.
- 공개 후기는 노출 사이트와 노출 위치를 각각 하나 이상 선택해야 한다.
- 삭제 대신 `ACTIVE`, `INACTIVE`, `ARCHIVED` 상태로 운영 이력을 보존한다.

## 5. 개인정보·동의 규칙

공개 API는 `ACTIVE`, 공개 설정, 홈페이지 공개 동의가 모두 충족된 후기만 반환한다.

- 표시 방식이 `MASKED`이면 서버에서 이름 가운데를 마스킹한다.
- `ANONYMOUS`이면 이름 대신 `익명`을 반환한다.
- 이미지 공개 동의가 없으면 이미지 URL을 반환하지 않는다.
- 취업정보 공개 동의가 없으면 취업 여부, 기업명, 직무, 취업 과정, 현재 직무 상세를 반환하지 않는다.
- 영상 공개 동의가 없으면 영상 URL을 반환하지 않는다.
- 내부 메모와 동의 확인 일시는 공개 DTO에 포함하지 않는다.
- 회원가입의 일반 개인정보 동의를 후기 공개 동의로 간주하지 않는다.

## 6. 홈페이지·과정 연결

- 공개 API 목록: `/v2/api/reviews`
- 공개 API 상세: `/v2/api/reviews/{id}`
- 후기 목록: `/v2/site/campus/reviews.html`
- 후기 상세: `/v2/site/campus/review-detail.html?id={reviewId}`
- 메인 홈페이지: `MAIN + HOMEPAGE_FEATURED + featured=true`
- 캠퍼스 홈페이지: `CAMPUS + CAMPUS_REVIEWS`
- 과정 상세: URL의 `courseId`와 `CLASS + COURSE_DETAIL`을 함께 적용
- 후기 목록 필터: 취업 기업, 직무, 과정, 수료 연도
- 후기 카드와 상세에서 연결된 공개 과정으로 이동할 수 있다.

홈페이지 고정 후기는 제거했으며 공개 데이터가 없으면 가상 후기를 생성하지 않고 빈 상태를 표시한다.

## 7. 기업·기관 CMS 재검증

`PartnerOrganization`은 관계 유형, 로고/설명/홈페이지, 노출 사이트·위치·순서와 과정 연결을 구조화한다. 공개 API와 홈페이지 렌더러는 공개 설정과 사이트·위치 조건을 적용한다. 후기 CMS는 취업 기업을 이 마스터에서 선택하므로 기업명을 중복 문자열로 관리하지 않는다.

실제 운영 로고·기관명 데이터와 홈페이지 게시 승인 자료는 별도 등록이 필요하다. 따라서 `공통-004`의 기능 구조는 구현, `취업-015`는 운영 데이터 등록 전까지 부분 구현으로 판정한다.

## 8. 테스트

`ReviewCmsFlowTest`에서 다음을 검증한다.

- 관리자 등록·수정과 과정/기업 연결
- 공개·비공개, 동의 여부, 사이트/위치, 정렬
- 이름 마스킹과 이미지/취업정보/영상 개별 동의
- 내부 메모 비노출
- 조건에 맞는 데이터가 없을 때 빈 배열
- 관리자 화면 렌더링과 강사 접근 차단
- 메인/캠퍼스/과정 상세의 동적 후기 영역

기업·기관, 과정, 신청 흐름의 기존 통합 테스트와 전체 Gradle 테스트로 회귀 여부를 함께 확인한다.

## 9. 남은 운영 작업

- 실제 수료생 후기 원문과 공개 범위별 동의 증빙 등록
- 승인된 수료생 사진·영상 URL과 취업 기업/직무 데이터 등록
- 승인된 기관 로고와 실데이터 등록
- 운영 브라우저에서 PC·모바일 레이아웃과 이미지 비율 최종 시각 검수
- 향후 필요 시 파일 업로드·보관 기간·동의 철회 이력·승인 워크플로 확장

## 10. 체크리스트 판정 근거

- `공통-003`: 관리자 통합 관리, 공개 동의, 사이트/위치/순서, 과정·기업 연결과 공개 화면이 구현되어 `구현`.
- `공통-004`: 기업·기관 마스터와 관계/노출/과정 연결이 구현되어 `구현`.
- `취업-015`: CMS·공개 롤링 구조는 구현됐으나 승인된 실제 기관 로고/목록 등록이 남아 `부분 구현`.
- `취업-017`: 사진·영상 URL, 단계별 인터뷰, 카드/상세 화면과 과정 연결이 구현되어 `구현`.
- `취업-018`: 취업기업·직무·과정·연도 필터와 관련 과정 연결이 구현되어 `구현`.

자동 테스트는 기능 근거로 사용할 수 있으나, 현재 실행 환경에 제어 가능한 브라우저가 없어 시각 검수 체크는 완료로 표시하지 않는다.
